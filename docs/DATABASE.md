# Database schema (PostgreSQL 17, Drizzle ORM)

Conventions: `snake_case` tables/columns; surrogate keys `bigint generated always as identity`
(`id`) except auth tables (text ids from Better Auth); `timestamptz` everywhere; localized text as
`jsonb` (`LocalizedText = { en: string, fr?: string, … }`, `CHECK (name ? 'en')`).
Monetary values (gems) are `bigint` with `CHECK (>= 0)` where a balance is stored.

## Entity overview

```
user (Better Auth) 1─1 player_profiles ─┬─< gem_transactions
                                        ├─< user_cards >── characters >──< series_characters >── series ─< media
                                        │                  characters >──< character_media >── media
                                        ├─< wishlist_items >── characters                     media ─< media_tags >── anilist_tags
                                        ├─< booster_openings ─< booster_opening_cards
                                        ├─< trades ─< trade_items
                                        ├─< market_listings
                                        ├─< user_counters
                                        ├─< user_missions >── missions
                                        ├─< user_achievements >── achievements
booster_tiers      themes ─< theme_characters >── characters      booster_openings >── booster_tiers, themes
rarities, settings, admin_audit_log, import_jobs
```

## Auth (managed by Better Auth, Drizzle adapter)

`user`, `session`, `account`, `verification` — generated by Better Auth CLI. Admin plugin adds
`role` (`user` | `admin`), `banned`, `ban_reason`, `ban_expires` on `user`. Sign-in is **Discord
only**: `account.account_id` holds the Discord user id (used by `ADMIN_DISCORD_IDS` bootstrap).

## Players and economy

### `player_profiles`

| Column                 | Type          | Notes                                                                            |
| ---------------------- | ------------- | -------------------------------------------------------------------------------- |
| user_id (PK, FK user)  | text          | 1–1 with auth user. Row is the **lock target** for all inventory/gem operations. |
| username               | citext UNIQUE | Public handle for profile URL `/u/:username`.                                    |
| locale                 | text          | `en`, `fr`…                                                                      |
| gem_balance            | bigint        | `CHECK (gem_balance >= 0)`                                                       |
| free_booster_anchor_at | timestamptz   | Timer anchor (see GAME_DESIGN §2). Default epoch: a new player starts full.      |
| created_at             | timestamptz   |                                                                                  |

Why a separate table: keeps Better Auth tables untouched (upgrades) and gives one row per player to
`SELECT … FOR UPDATE`.

### `gem_transactions` (append-only ledger)

`id, user_id, amount (bigint, signed), balance_after, reason (enum: booster_purchase, recycle,
market_sale, market_purchase, mission_reward, achievement_reward, admin_adjustment), ref_type, ref_id,
created_at`.
Index `(user_id, created_at desc)`. Invariant checked by a test/admin tool:
`sum(amount) = gem_balance` per user.

## Catalog

### `series`

`id, slug UNIQUE, kind enum(anime, game, other), source enum(anilist, manual), title,
title_english, description, cover_url, cover_upload_path, genres text[] (manual series only),
is_active (default true), primary_media_id NULL, popularity, created_at, updated_at`.
Index on `is_active`. An AniList series groups related media (seasons, movies) — see ADR-014;
a manual series (e.g. a gacha game) has no media.

### `media`

`id, anilist_id UNIQUE, series_id FK NULL, format, title_romaji, title_english, title_native,
description, season_year, popularity, favourites, is_adult, genres text[], cover_url, site_url,
franchise_relations int[], fetched_at, characters_synced_at, updated_at`.
Indexes: `series_id`; GIN on `genres`.

- `series_id` is null only between the discovery and grouping steps of an import.
- `franchise_relations`: AniList ids linked by a franchise relation (SEQUEL, PREQUEL, PARENT,
  SIDE_STORY, ALTERNATIVE, SUMMARY); grouping re-reads them from the database, so a resumed
  import does not fetch them again.
- `fetched_at` / `characters_synced_at` compared with `import_jobs.started_at` tell a resumed job
  what is already fresh.

### `anilist_tags` / `media_tags`

`anilist_tags(id, anilist_id UNIQUE, name, category, is_adult)`;
`media_tags(media_id, tag_id, rank smallint)` PK `(media_id, tag_id)`, index `(tag_id, rank)`.
Rank (0–100 relevance) is required for "Shounen ≥ 60" rules.

### `characters`

| Column                                             | Type                             | Notes                                                       |
| -------------------------------------------------- | -------------------------------- | ----------------------------------------------------------- |
| id                                                 | bigint                           |                                                             |
| source                                             | enum(anilist, manual)            | `CHECK (source = 'anilist') = (anilist_id IS NOT NULL)`.    |
| anilist_id                                         | int NULL UNIQUE                  | Upsert key for re-imports (NULL for manual characters).     |
| manual_key                                         | text NULL UNIQUE                 | `<series slug>/<roster key>`: upsert key of roster imports. |
| name_full, name_native, name_alternatives (text[]) |                                  | As provided by AniList.                                     |
| description                                        | text                             | AniList markdown (rendered sanitized).                      |
| image_url                                          | text                             | AniList CDN.                                                |
| image_path                                         | text NULL                        | Uploaded image, or cached copy under `cache/` (see below).  |
| gender_raw                                         | text NULL                        | AniList value.                                              |
| gender_class                                       | enum(female, male, unclassified) | Derived at import.                                          |
| gender_override                                    | enum NULL                        | Admin decision, wins over `gender_class`.                   |
| favourites                                         | int NULL                         | Drives default rarity (NULL for manual characters).         |
| rarity_id                                          | FK rarities                      |                                                             |
| rarity_overridden                                  | bool                             | Re-import never changes rarity when true.                   |
| is_active                                          | bool                             | Admin can disable a single character.                       |
| updated_at                                         | timestamptz                      |                                                             |

Indexes: `(rarity_id) WHERE is_active`, trigram GIN on `name_full` (pg_trgm) for search.

Image cache: the worker stores copies of remote images as `image_path` (and
`series.cover_upload_path`) under the `cache/` prefix. `BEFORE UPDATE` triggers clear a `cache/`
path when `image_url` (`cover_url`) changes, so a new remote image is never hidden by a stale copy;
uploaded images (no prefix) are never touched.

### `igdb_games` / `character_games` (IGDB, ADR-025)

- `igdb_games(id, igdb_id UNIQUE, series_id FK series, name, summary, cover_url, rating_count,
genres text[] (genres + themes, AniList spelling when equivalent), themes text[], release_year,
site_url, characters_synced_at, updated_at)`. A game belongs to the series of its first IGDB
  collection (`series.igdb_key = 'collection:<id>'`) or to a series of its own (`'game:<id>'`).
- `character_games(character_id, game_id)` PK both; index `game_id`. Series membership of IGDB
  series is rebuilt from it. IGDB characters have `source = 'igdb'`, `igdb_id` (unique, checked
  against the source), `site_url` and `game_popularity` (rating count of their most popular game,
  ADR-026); `rarities.game_popularity_threshold` gives their default rarity.

### `character_media`

`(character_id, media_id, role enum(MAIN, SUPPORTING, BACKGROUND))` PK both ids, index `media_id`.

Provenance only: which AniList media a character appears in (used by tag/genre/format rules).

### `series_characters`

`(series_id, character_id)` PK both, index `character_id`. **Canonical** series membership for
every source: derived from `character_media` for AniList series (rebuilt at import), edited
directly for manual series. Series progress and completion use this table.

A character is **drawable** when `is_active` and linked to at least one active series. A view
`drawable_characters(character_id, rarity_id)` centralizes this rule.

## Rarities, rates, boosters, themes

- `rarities(id, key UNIQUE, sort_order UNIQUE, name jsonb, color_token, favourites_threshold,
recycle_value, market_min_price, market_max_price)`. Changing a threshold re-applies the default
  rarity of AniList characters whose rarity was not set by hand.
- `booster_tiers(id, key UNIQUE, name jsonb, description jsonb, weights jsonb -- { rarityKey: ppm },
price_gems bigint NULL (NULL = free tier), is_active, sort_order, art_token)`.
  Weights sum = 1 000 000 enforced by Zod + test.
- `themes(id, key UNIQUE, category enum(demographic, genre, characters, media_type, custom),
name jsonb, description jsonb, rules jsonb, seal text (1–2 characters, default 招), art_token,
is_active, sort_order, pool_built_at, updated_at)`. Packs are opened with free boosters only.
- `theme_characters(theme_id, character_id)` PK both; index `character_id`. Materialized membership.

An opening = tier + optional pack (`theme_id`, free tier only; NULL = whole catalog) (ADR-018).

### Openings (audit + reveal history)

- `booster_openings(id, user_id, tier_id, theme_id NULL, quantity, gems_spent, created_at)` index `(user_id, created_at desc)`. `theme_id` is added with themed packs (Phase 5).
- `booster_opening_cards(opening_id, position smallint, character_id, rarity_id, is_new bool)` PK `(opening_id, position)`.

Volume estimate: an active player ≈ 70 boosters/day → 350 card rows/day. Acceptable; a retention
setting (e.g. 90 days) can prune it later via the worker.

## Inventory

### `user_cards`

| Column                | Type        | Notes                                                                                                        |
| --------------------- | ----------- | ------------------------------------------------------------------------------------------------------------ |
| user_id, character_id | PK          |                                                                                                              |
| quantity              | int         | `CHECK (quantity >= 0)`                                                                                      |
| locked_quantity       | int         | `CHECK (locked_quantity >= 0 AND locked_quantity <= quantity)` — copies in active listings / pending trades. |
| first_obtained_at     | timestamptz | **Wiki unlock** = row exists (kept even when quantity reaches 0).                                            |
| last_obtained_at      | timestamptz | Sort "recent".                                                                                               |

Indexes: `(user_id) WHERE quantity > 0`, `(character_id) WHERE quantity > 0` (who owns it — trades).
Why stacks instead of one row per card: copies are identical, a 10x opening is ≤ 50 upserts, and
duplicate/lock arithmetic is trivial with check constraints guarding invariants (ADR-008).

### `wishlist_items`

`(user_id, character_id)` PK, `created_at`. Index `character_id` (who wants it — market highlight).

## Trades and market

- `trades(id, proposer_id, recipient_id, status enum(pending, accepted, declined, cancelled,
countered, expired, failed), parent_trade_id NULL, message, created_at, responded_at, expires_at)`.
  Indexes: `(recipient_id, status)`, `(proposer_id, status)`.
- `trade_items(trade_id, side enum(proposer, recipient), character_id, quantity)` PK `(trade_id, side, character_id)`.
- `market_listings(id, seller_id, character_id, price bigint, status enum(active, sold, withdrawn,
expired), buyer_id NULL, created_at, expires_at, closed_at)`.
  Indexes: partial `(character_id, price) WHERE status='active'`, `(seller_id, status)`,
  `(buyer_id, closed_at)` for daily purchase limit, `(seller_id, closed_at) WHERE status='sold'` for daily sale limit.

## Progression

- `user_counters(user_id, key text, value bigint)` PK `(user_id, key)`.
- `missions(id, key UNIQUE, name jsonb, description jsonb, kind enum(daily, once), event_type,
filter jsonb, target int, reward_gems, is_active, sort_order)`.
- `user_missions(user_id, mission_id, period_key text, progress int, completed_at, claimed_at)`
  PK `(user_id, mission_id, period_key)`. `period_key` = `YYYY-MM-DD` of the reset period or `once`.
- `user_mission_dedup(user_id, mission_id, period_key, subject_id)` PK all — e.g. a wishlist
  character counted once per day.
- `achievements(id, key UNIQUE, name jsonb, description jsonb, metric text, params jsonb, target
bigint, reward_gems, icon_token, is_active, sort_order)`.
- `user_achievements(user_id, achievement_id, progress bigint, completed_at, claimed_at)` PK both.
  Index `(achievement_id) WHERE completed_at IS NULL` for bulk recomputation.

## Misc

- `settings(key PK, value jsonb, updated_at, updated_by)` — validated with a Zod schema per key in
  `@app/shared` (free booster interval/cap, mission reset hour/timezone, market limits, rarity
  thresholds toggle, image cache enabled…).
- `catalog_state(id = 1, version uuid)` — a single row. Statement-level triggers on `characters`
  (insert, delete, `is_active`, `rarity_id`), `series` (delete, `is_active`), `series_characters`
  and `theme_characters` give it a new random version whenever drawability or a pack pool may
  change. Processes cache booster pools per version (ADR-024).
- `admin_audit_log(id, actor_id, action, target_type, target_id, before jsonb, after jsonb, ip, created_at)`
  index `(created_at desc)`, `(target_type, target_id)`.
- `import_jobs(id, requested_by, params jsonb, status enum(queued, running, completed, failed,
cancelled), progress jsonb, error, created_at, started_at, finished_at, updated_at)`. `progress`
  holds the current phase (discover → group → characters → finalize → done), counters and the
  discovered AniList ids. Only one job may be queued or running at a time.

## Migrations

drizzle-kit generates SQL migrations into `packages/db/migrations` (committed, never edited after
merge). Constraints Drizzle cannot express (partial indexes, triggers, pg_trgm) are added in custom
SQL migrations. Seed is idempotent (upsert by `key`).
